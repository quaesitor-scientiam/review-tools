Fast Path
1. Establish full scope

Review the full PR diff against merge base, then read every changed file in full. Do not rely on the last incremental commit.

1b. Select the review mode (rev 41)

Right after scope, before reading files in full: classify Lite / Standard / High-risk / Regression from file/domain evidence. Determines whether the Phase 1 candidate cap applies and whether matrices/artifacts may be marked N/A liberally. See Review Modes below.

2. Derive contracts

For any repeat-offender function (touched by an earlier commit on this branch) and for every NEW type/function/branch, write its one-paragraph contract from scratch before scanning angles, then diff it against the nearest existing sibling.

3. Do fresh-eyes review

Before the checklist, ask what the least obvious breakage could be. This catches consistency bugs that checklist framing misses.

4. Run mechanical detectors

Run run_detectors.sh next, after fresh-eyes and before A-K. Treat detector output as candidates requiring verification, not automatic findings.

5. Walk A-K angles

Use Angles for systematic coverage: new lines, removed behavior, caller/callee contracts, whole-file invariants, protocol rules, concurrency, security, and absence search (rev 36: what MUST exist but has no diff line).

6. Check domain gates

Admission-gate invariants, the H2/QUIC RFC conformance matrices, and swallowed-write-error windows — the mandatory protocol/concurrency-specific checks layered on top of the general angles.

7. Triage candidates

Classify each candidate as CONFIRMED, PLAUSIBLE, or REFUTED. Speculative means PLAUSIBLE unless a specific line makes it impossible.

8. Verify and regress

For real misses, reproduce when possible, add a regression test or detector, and update the Bug Corpus or Process Lessons.

9. Adversarial Workflow pass (rev 53)

For non-trivial work (Standard mode and above), after Phase M's marker is written: spawn independent agents via the Workflow tool instructed to REFUTE specific findings/functions, not confirm them. Standing user opt-in — invoke without asking each time. Skip for Lite-mode diffs.

Review Modes (rev 41)

The full process is expensive; not every diff needs the same amount of it. Pick exactly one mode from file/domain evidence right after establishing scope, before the deep Phase 0 work — state which and why as part of the Phase 0 checklist. An explicit $ARGUMENTS mode overrides auto-detection, but the auto-detected evidence must still be stated so a downgrade is visible, not silent.

Lite

Diff touches ONLY docs, test files, or local/non-shared code with no protocol/concurrency/security/cross-file surface. Full-file reads and Phase 0 artifacts stay required, but “N/A” is the expected answer for most of them — state it explicitly rather than skip the field. Exception (rev 75): a test-only diff that adds a regression test, or rests on an “already fixed” claim, is never Lite. It takes the mode of the code under test: read the fixed function in full and list every writer of the state the fix corrects, each with a test that reaches it or a reason it cannot.

Standard (default)

Ordinary production changes with no High-risk-domain surface. Run the full process as documented throughout this reference, at full strength.

High-risk

Diff touches protocol code (H2/QUIC/HTTP), the parser/scanner/checker, a new or widened diagnostic, rejection or validation gate in any tool (Angle K applies in full, rev 80), crypto/TLS, an unsafe{} block, concurrency primitives, or manual resource-lifetime code. Even a small diff in these domains has a track record of hiding real findings — see the Bug Corpus.

Regression

This review is running because an external reviewer already found a miss in a prior pass on this exact code (Phase R). A confirmed miss raises the prior on siblings elsewhere in the same PR — treat the whole PR at High-risk rigor.

High-risk and Regression both: disable the Phase 1 per-angle candidate cap (“up to 6” becomes uncapped — surface every candidate an angle finds) AND require every applicable matrix/artifact (sibling parity table, Angle E's conformance matrix rows, Angle F's three concurrency matrices, Angle H's absence-search checklist) to be FULLY populated. In these two modes “N/A” for a plausibly-applicable angle is itself a claim needing justification, not a default — the opposite of Lite mode's normal N/A discretion.
Required Artifacts (rev 33)

Every rule above says “must”, but multiple corpus rows trace back to a rule that existed and simply wasn't executed that pass (an abbreviated review, a detector never invoked, an angle skipped under time pressure). A prose instruction with no artifact is not checkable after the fact — these 10 are now REQUIRED parts of the review's own Output format, not optional detail. An item silently left blank is indistinguishable from a step that never ran; mark it “none”/“N/A”/“not run” explicitly instead. Phase M's marker now means this block was filled in, not just the findings list.

Review mode (rev 41)

Lite / Standard / High-risk / Regression, with the files/domains that justify it — stated right after scope, before the deep Phase 0 work. Determines whether the Phase 1 candidate cap applies and how liberally other artifacts below may be marked N/A.

Per-file contract paragraph

One paragraph per file read in full (Phase 0 step 4): its invariants, before/after state, shared state touched. This is the proof the read happened, not a summary of it.

Repeat-offender list

One row per flagged function: function — file:line — prior commits touching it — pass/fail against its from-scratch contract. State “none” explicitly if empty.

New type/function contract list

Same row shape, one per NEW struct/method/function this diff introduces. State “none” explicitly if the diff adds none.

Sibling parity table (rev 37)

6 columns: new path | sibling | sibling caller guards | matched behavior | intentional divergence | unresolved divergence. Sibling caller guards is what catches a #27712-shaped miss (a guard living in the sibling's CALLER, not its body); unresolved divergence is the actual finding column. If no sibling exists anywhere in the codebase, say so in the sibling column rather than skipping the row.

Detector run log

The actual run_detectors.sh command and its output — or the specific reason a detector didn't run (platform-gated, file type absent). A detector that exists but was never invoked is the single most common way a “must” goes unexecuted.

Matrix rows checked

For H2/QUIC changes: row (requirement) — file:line/commit — CONFORMS/GAP/ADVISORY, including rows confirmed unaffected, not just diff-adjacent ones. “N/A” if no H2/QUIC changes.

Concurrency matrices (Angle F, rev 38)

Three tables: (1) shared field → readers → writers → lock, (2) wait predicate → all mutators → wake/broadcast path, (3) action sized under lock → committed under same protection? State “none” per matrix with no applicable rows rather than omitting it.

Negative evidence / skipped areas

What this review deliberately did NOT cover and why — effort-level constraints, excluded files, skipped angles, unwalked matrix sections. A silent gap reads as “checked and clean”; a stated gap reads as “not checked”.

Absence-search checklist (rev 36)

One line per Angle H question: the requirement/check/path considered, present (file:line) or GAP, fixed or logged. State “none applicable” explicitly for a question that doesn't apply to this diff.

Phase 0 — Gather the diff and full file content

Why full-PR scope matters

The dominant source of missed findings is reviewing only the last incremental commit. When the branch tracks origin/<branch> and you just pushed, git diff @{upstream}...HEAD is empty. Codex always reviews the full PR diff against the merge base; this skill must match that scope.

Steps

  • Find the merge base: git merge-base <base> HEAD
  • Get the full PR diff: git diff $(git merge-base <base> HEAD)...HEAD
  • Fold in uncommitted work: git diff HEAD
  • Classify each .v file as NEW or MODIFIED
  • Select the review mode (rev 41) — Lite / Standard / High-risk / Regression from file/domain evidence, before the deep Phase 0 work below. High-risk and Regression disable the Phase 1 per-angle candidate cap and require every applicable matrix/artifact fully populated, not liberally N/A'd. See Review Modes on the Review Recipe tab. Artifact: the chosen mode plus the evidence for it.
  • Read every file in the diff IN FULL — for NEW files, every line is in scope. Bugs in untouched lines of new files are the most commonly missed class. Artifact (rev 33): one per-file contract paragraph per file read — the proof the read happened, not a summary of it.
  • Flag repeat-offender functions (rev 13) — any function touched by an EARLIER commit on this branch needs a from-scratch one-paragraph contract re-derivation checked against every line of its CURRENT body, not another diff-only scan. Artifact (rev 33): a repeat-offender list (function — file:line — prior commits — pass/fail); state “none” explicitly if empty.
  • New types/functions get the SAME contract check (rev 16) — being new is not a reason for less scrutiny; write the one-paragraph contract for every NEW struct/method this diff introduces too, before running Angle A–K on it. Artifact (rev 33): a new type/function contract list, same row shape; state “none” explicitly if the diff adds none.
  • Closest-sibling parity diff (rev 16) — for every new type/function/branch, find the nearest existing analog elsewhere in the codebase and diff intent clause by clause; three of round 5's six findings had a correct sibling sitting one function or one file away. Scope = the sibling's CALL PATH, not just its body (rev 18) — a guard in the sibling's CALLER (capability gate, platform check, admission guard) is part of the sibling's effective contract; grep the mirrored sibling's callers and treat every condition they check before calling it as a parity candidate (#27712 round 1: the pre-8.1 ALPN gate lived in vschannel_ssl_do, not in the mirrored vschannel_h2_do itself). Artifact (rev 37): a 6-column sibling parity table — new path | sibling | sibling caller guards | matched behavior | intentional divergence | unresolved divergence. The sibling caller guards column is what would have caught the #27712 miss above (a body-only diff has no column for it); matched behavior is positive evidence the comparison happened at all; unresolved divergence is the actual finding column — every non-empty entry there is a Phase 1 candidate. If no sibling exists anywhere, say so in the sibling column rather than skipping the row.
  • A verification gate is a sibling of the build it approves (rev 63) — when a diff adds a smoke test, post-build self-check or install precondition for a freshly built artifact, the build command that produced the artifact is its sibling: every toolchain/configuration flag of the build (-cc, -cflags, a target triple) must reach the check, or the check validates a different configuration than the one being installed. vlang/v#30278 (medvednikov, pullrequestreview-5531629970): makev.bat’s new :smoke_test_updated compiled hello world with no -cc while every build of v_up.exe passed one, so a -msvc --local clone with no bundled TCC built a working MSVC compiler and refused to install it. Add one parity row per gate with the build line as the sibling; mechanical check: cmd/tools/makev_test.py test_install_smoke_tests_with_the_toolchain_that_built_the_compiler.
  • A sibling can share a namespace, not only logic (rev 77) — when new code allocates a name, id, slot or key, compare the set it checks against every sibling allocating from the same space, and list what each has already taken. vlang/v#31799: the FastC rename mirrored the constant collision pass in shape, then reused a name that pass had allocated.
  • A renamed EMITTED symbol has callers too (rev 64) — when a diff changes the C name a definition is emitted under (an entry point, an exported wrapper, a mangled helper), the references to trace are every rendering path that spells that name (calls, function values, prototypes, &name), not the V callers of the function you changed; grep the OLD spelling as a key/string literal across the generator and resolve definition and references through ONE funnel. vlang/v#30672 (medvednikov, pullrequestreview-5541265161): the fastc entry became wmain on Windows at its definition only, while fn again() { main() } and f := main still rendered main via c_function_name_for_key. Regression test vlib/v/gen/fastc/windows_entry_call_test.v fails on d2c3084ada.
  • Declare what this review does NOT cover (rev 33) — effort-level constraints, excluded files, skipped angles, unwalked matrix sections, detectors not run: every deliberate exclusion must be named, not left for a reader to infer from absence. Artifact: negative evidence / skipped areas. A silent gap reads as “checked and clean”; a stated gap reads as “not checked” — only one of those is true when a step was skipped.

Common mistake

"The diff is small, targeted reads of the enclosing function are enough." That rationalization is the bug. If a file is NEW or the change touches protocol/concurrency logic, read it top to bottom.

Phase 1 — Find candidates (run inline, no sub-agents)

Fresh-eyes pass first, no checklist (rev 16)

Before the structured angles: one pass with NO list at all. A checklist walk guarantees known bug classes never get skipped, but by construction it can't surface a shape nobody's written a bullet for yet — 4 of round 5's 6 findings were bug shapes with no existing angle at all, missed by a COMPLETED A–I pass, not a skipped one. Read the diff and full files once, set aside anything already decided earlier in the session, and ask only: if a stranger saw this cold, with no checklist and no memory of why it was written this way, what's the least obvious way it breaks?

Then work through every angle yourself. Each surfaces up to 6 candidates (uncapped in High-risk/Regression mode — rev 41) with file, line, a one-line summary, and a concrete failure_scenario.

Never silently drop half-believed candidates — that is the dominant cause of misses. Every candidate with a nameable failure scenario must reach triage.

Where detectors and domain gates fit

Run run_detectors.sh after the fresh-eyes pass and before working the A–K angles by hand — its output is a first pass of candidates, not a substitute for the angles (individual angles also cite specific detectors to verify a suspected finding). Artifact (rev 33): a detector run log — the command actually run and its output, or the specific reason a detector didn't run. A detector that exists but was never invoked this review is the single most common way a “must” rule goes unexecuted; several Bug Corpus rows below are exactly this ("the detector wasn't even run", "angles not actually run") — the log is what makes that visible instead of assumed. After A–G, walk the domain-specific gates that sit on top of the general angles: Angle D's admission-gate invariant, Angle E's standing H2/QUIC RFC conformance matrices (artifact: matrix rows checked), Angle F's swallowed-write-error windows, and Angle H's absence search (artifact: absence-search checklist — rev 36). These are mandatory, not optional extensions of A–I, because they catch absent requirements a diff-driven angle pass structurally can't surface.

Phase 2 — Triage
  • Dedup near-duplicates (same defect, same location → keep most concrete)
  • Classify each: CONFIRMED, PLAUSIBLE, or REFUTED
  • Drop REFUTED only; keep every CONFIRMED and PLAUSIBLE candidate, ranked most-severe first — no retention cap (rev 35). A hard cap at triage silently discards real findings past the Nth, throwing away the work the fresh-eyes pass and A–K angles just did to surface everything.
  • Default to PLAUSIBLE for: races, nil on error paths, off-by-one near boundaries, protocol edge cases a peer is permitted to exercise
  • Final report only — if the presented list needs shortening for readability (an unusually large PR), truncate the presentation, not the underlying set: state the true total count and how many were omitted, never truncate silently.
Phase 3 — Optional sub-agent verification

Only at max effort AND if sub-agent session limits allow. One verification agent per CONFIRMED finding to independently confirm. If agents hit session limits, mark findings "unverified — verify manually before acting."

Phase A — Adversarial Workflow pass (rev 53)

Why this is not the same thing as Phase 3

Phase 3 verifies candidates this same self-review pass already surfaced — it shares the author's blind spots and can only confirm the existing candidate set, never widen it. Phase A is a genuinely separate second pass: fresh agents with no stake in the code being right, spawned via the Workflow tool and instructed to actively refute specific functions/claims rather than confirm them. It exists because self-review — even a full A–I pass plus Phase 3 — kept missing findings external reviewers (Codex, GPT-5.6 Luna) caught on later rounds of the SAME already-self-reviewed diff. See Bug Corpus: Phase 11 QPACK's RIC-tracking and malformed-vs-truncated rows, both self-reviewed clean, both caught by Luna.

When it runs

  • Non-trivial programming work: new subsystems, protocol/concurrency logic, anything that would otherwise get a stated confidence or completeness claim. Standard mode and above — skip for Lite-mode diffs (docs, tests, local non-shared code).
  • After Phase M's commit-gate marker is written, before reporting the work complete or opening/updating the PR — it is a final gate on top of a self-review pass that already passed, not a substitute for one.

How it's invoked

Standing user opt-in (2026-08-16, confirmed general — “any programming efforts,” not scoped to this repo): call the Workflow tool for this purpose without asking permission each time. The script spawns N independent agents, each given one specific finding/function/claim and instructed to try to refute it (default to refuted=true when uncertain, per the adversarial-verify pattern) — this is not a second run of the A–K checklist. A claim stays reported only if it survives refutation by a majority of the independent agents. Calibrate any stated confidence to what was actually independently checked this way, not to how thorough the self-review pass felt. Rev 80: write every classifying sentence in the brief as a hypothesis for finders to test, and add a mandatory acceptance-regression lens for a diff that adds or widens a rejection: its finder constructs inputs the previous build accepted and the new one refuses, and runs them through both builds. Rev 81: an empty confirmed is a clean result only if every agent ran. Check for failed agents first and treat any non-empty unverified list as an unfinished round to resume.

Phase R — Reproduce a miss, close the gap

The principle

Every miss is a failing test for the review. The point is not just to fix the bug — it is to prove the review would now catch it, and to leave a permanent regression behind.

6 Steps

  • Record — commit, file:line, bug class (lenient-parse, error-scope, sibling-arm, …)
  • Diagnose with evidence, not a default (rev 40) — the corpus shows present-but-not-run is usually the answer, but that history is context, not license to assume it. Three required fields: existing rule that should have caught it (name the angle+bullet/detector/matrix row precisely, or the honest answer is “none”); why it failed (never run? eyeballed instead of executed? a confirmed structural blind spot? scope narrower than this instance?); new enforcement mechanism (which Phase R step 3 type closes THIS failure — “run it next time” is not a mechanism). “None” on the first field means missing, not a softer present-but-not-run.
  • Pick the remediation (rev 39) — a detector is the DEFAULT, not the only option; prose reminders don't survive "I forgot", but forcing every miss into a grep script that can't express it doesn't either. Six options below.
  • Reproduce — adapt to the chosen remediation: run detector/test against the reviewed commit (MUST fire/fail); confirm a matrix row is filed GAP citing the buggy commit; confirm the OLD artifact schema wouldn't have surfaced the finding; or confirm a checklist rule/limitation cites the commit as its worked example
  • Confirm fix clears — detector/test passes on working tree; matrix row flips GAP→CONFORMS; NEW artifact schema surfaces the finding
  • Log it — add to reference/code-review-misses.md and code-review-misses-data.js with repro command (or matrix row / schema change / rule citation) AND the three diagnosis fields verbatim, so a later reader can audit whether present-but-not-run was evidenced or assumed

Step 3 — the six remediation types

Detector, matrix row, and regression test are mechanical — the ones that survive “I forgot to think about it,” and still the right default whenever the defect has a checkable signature. Checklist rule and documented limitation are for when it genuinely doesn't — using them to skip the work of a real mechanical check is the exact prose-reminder failure this step exists to prevent.

  • Detector (default) — a grep/script that exits non-zero on the defect. Use when the defect has a stable syntactic signature, no dataflow analysis needed.
  • Conformance matrix row — the miss is an absent MUST Angle E already tracks (H2/QUIC). File a GAP row citing the buggy commit, close it, flip to CONFORMS.
  • Regression test — the defect needs runtime/dataflow evidence a static grep can't see (leak, race, wrong runtime value). The test IS the check: fails on buggy code, passes after the fix.
  • Required artifact/table — the miss reveals an existing REQUIRED artifact's schema is missing the column/row-type that would have surfaced it (precedent: the sibling parity table gaining “sibling caller guards” after a caller-guard miss). The fix changes the review PROCESS artifact, not the reviewed code.
  • Checklist rule — the defect needs semantic judgment no script can make. A new, concrete prose bullet in the relevant angle with the historical miss as its worked example — most of Angle F's existing bullets are this shape.
  • Documented detector limitation — an existing detector genuinely CANNOT be extended to this shape (confirmed, not assumed — e.g. re-aliasing before a free, 2+ levels of struct nesting). State the limitation explicitly rather than letting a future reviewer trust a detector that's structurally blind to it.

The skill uses three complementary layers. SKILL.md is the cognitive layer — prose instructions Claude reads and executes as reasoning steps. The detector scripts are the mechanical layer — shell scripts that exit non-zero when a specific invariant is violated, eliminating the “I read it and it looked fine” failure mode. The conformance matrices (${CLAUDE_PLUGIN_ROOT}/skills/code-review/h2_conformance_matrix.md, and as of rev 23 quic_conformance_matrix.md) are the requirements layer — a requirements-driven map of every normative MUST (RFC 9113/7541 for H2; RFC 9000/9001/8446/7301 for QUIC) to a file:line or commit. A diff-driven review reacts to what changed; only an enumerated requirements list makes a missing MUST visible. The proactive audit that built the H2 matrix (2026-06-27) found gaps G1/G2/G4 no external review had flagged; the QUIC matrix's own first audit (2026-07-26) repeated that exact result, finding a client-side initial_source_connection_id gap no Codex round had reported. As of 2026-07-02 every H2 server row is ✅ — the h2spec expected-failures baseline is empty (146/146) and CI fails on any h2spec failure.

SKILL.md — Cognitive Layer

When you run /code-review, Claude reads SKILL.md as its instruction set. It defines what to do, in what order, and how to think about findings. There is no code runner at this layer — it is pure prose the model executes as reasoning steps.

  • Phase 0 — scope the diff (always git merge-base … HEAD, never @{upstream}), read every touched file in full, then three from-scratch contract checks (rev 13/16): a repeat-offender function touched by an earlier commit on this branch, ANY brand-new type/function this diff introduces, and a closest-existing-sibling parity diff for every new type/function/branch
  • Phase 1 — a mandatory unstructured “fresh eyes, no checklist” pass FIRST (rev 16), then seven independent structured angles, each a different lens; a miss on one angle cannot hide a bug from another
  • Phase 2 — how to classify findings (CONFIRMED / PLAUSIBLE / REFUTED) and the burden of proof for each
  • Phase A (rev 53) — independent Workflow-spawned agents try to REFUTE findings/functions rather than confirm them; a genuinely separate reviewer, not another pass by the same author. Standing user opt-in, general to all programming work.
  • Phase R — what to do when an external reviewer finds something the review missed
  • Phase M — write the review-marker fingerprint the commit-gate hook checks; not optional — skipping it blocks every subsequent git commit/git push

The critical behavioral rule embedded throughout SKILL.md: don’t eyeball — run the script. Almost every angle with a mechanical check includes the exact bash command and says explicitly “do not scan by eye.”

Detector Scripts — Mechanical Layer

The scripts are the antidote to a failure mode that was DOMINANT through round 4 of the corpus: “an angle existed but was eyeballed instead of executed.” Every time a pattern was missed that way, Claude read the relevant code, decided it looked fine, and produced no candidate — instead of running a check that would have caught it. That mode is now largely mechanized away by the table below; the harder remaining failure mode, dominant in round 5 and the self-caught round-6 bug, is the opposite shape — no angle existed at all to eyeball or run (4 of round 5's 6 findings, and the standalone round-6 refcount bug). The rev-16 fresh-eyes Phase 1 pass and the Phase 0 sibling-parity/contract checks above target THAT gap; a script only exists once a pattern has been seen at least once.

Each script enforces one invariant and exits non-zero when that invariant is violated, printing the exact file and line. There is no ambiguity and no opportunity to rationalize “it looks fine.”

How They Interact During a Review

SKILL.md instructs Claude to run the scripts as mandatory gates within each angle. The prose in each angle describes what to think about; then it says “run the mechanical detector — do not eyeball” with the exact command. Claude executes the script via the Bash tool, reads the output, and incorporates any findings into Phase 1 candidates.

Script exit 1
Finding goes directly to triage as CONFIRMED — the invariant was violated and the exit code proved it. No burden-of-proof debate needed.
Script exit 0
That invariant holds for this diff. Prose reasoning for the same class of bug can still surface a PLAUSIBLE candidate if context suggests a gap the script doesn’t cover.
Phase R
When a reviewer finds a miss: make it a script, not a prose reminder. Prose reminders get forgotten. Scripts don’t.

Scripts collapse an entire class of bugs from “plausible if I think carefully enough” to “confirmed because the exit code said so.” Phase R closes the loop: every external-reviewer find becomes a new script that will catch that class permanently.

Selection: an internal manifest maps each detector to the target files it applies to (mux-only detectors run only against h2_mux_conn.v, server-only against h2_server.v, etc.). With no args, targets are the changed .v files (working tree vs HEAD plus branch vs merge-base with master).

detect_error_scope.v <file...>
Finds: return error(...) inside reader-thread functions (dispatch_frame, on_response_data, on_rst_stream, on_settings, on_ping, on_window_update, on_goaway, etc.).
Why dangerous: return error in a reader-thread function propagates to read_loop and triggers fail_conn(), tearing down EVERY in-flight stream. Per-stream faults must use reset_stream / cancel_stream (RST_STREAM + wake one waiter).
Strategy: for each return error line, scans backward up to 60 lines for the nearest function signature; flags if it matches a known reader-thread function name.
Output: each candidate shows the enclosing fn name and the return-error line. Confirm: is this a true connection-level fault (correct to escalate) or a per-stream fault that should RST instead?
Keep READER_FNS complete: the single-threaded server runs every handler on the reader thread, so the list must include on_headers/on_continuation/on_trailers/finalize_headers/finalize_trailers/on_data, not just the client mux fns. Missing on_trailers let its “trailers without END_STREAM” connection-abort slip past (#27569). Add each new per-stream handler when a driver gains one. (Slow on Windows git-bash — run in WSL.)
grep -nE '^\s*return\s+error' → backward scan for fn sig → match reader-thread names
Targets: error-scope class (on_response_data stream-recv-window, PR #27413)

Finds: the wmu→fmu recheck block in send_body_on_stream is missing an s.send_window < 0 guard after the inner fmu.lock().
Why dangerous: The reader applies an INITIAL_WINDOW_SIZE delta to s.send_window under fmu. Reusable Review Lessons
Separate bugs from method failures

Concrete defects belong in Bug Corpus. Stale matrices, skipped checks, detector blind spots, and review-process failures belong here.

Re-audit deferred matrix rows

Before using a matrix as evidence of coverage, grep deferred rows and cross-check changed files against branch history.

Read the whole cited spec section

Do not verify only the quoted sentence. Adjacent MUSTs and inverse rules have produced real misses.

Phase-R detectors before trusting them

A detector is useful only after it flags a known-buggy tree and passes a fixed tree, or its limitation is explicitly documented.

Sibling parity includes caller context

When mirroring a sibling function, inspect the sibling's callers and preconditions, not only its body.

A gate is a sibling of what it gates (rev 63)

A smoke test or self-check must run with the same toolchain and configuration flags as the build it approves; otherwise it tests a different configuration and rejects working builds on the machines where the explicit choice mattered.

Definition and references share one resolver (rev 64)

A platform- or mode-specific emitted name belongs in the single function both the definition and every reference call, never in the definition’s own branch; otherwise the second resolver keeps emitting the old spelling.

Fresh-eyes before checklist

Run an unstructured pass before A-K. The checklist is coverage, not a substitute for asking how the design breaks.

Self-review alone is structurally insufficient (rev 53)

Author and reviewer sharing a head means shared blind spots survive any checklist depth. A full A-I pass plus Phase 3 verification still missed QPACK's RIC-tracking and malformed-vs-truncated bugs, both caught by Luna. Phase A adds a genuinely independent adversarial pass, not more rules for the same reviewer.

Admission gate
A boolean check (can_take_new_request(), !c.shutting_down) that blocks new work from entering a resource. Bug pattern: the gate field is set on the happy path but not on an error sub-path, so another goroutine sees the resource as healthy when it is not.
Angle
One independent lens the review applies — a specific question to ask about the diff. Angles are independent so that one angle's failure does not block another's findings.
condvar / cv signal
A condition-variable signal that wakes a goroutine blocked in cv.wait(). A missed signal means a waiter blocks forever. Every state transition a waiter depends on must trigger a signal.
constant-time comparison
A string comparison that always examines all bytes regardless of where bytes differ, preventing an attacker from inferring the shared prefix length via response timing. V's == on strings is NOT constant-time. Required for any comparison involving secret material (tokens, keys, passwords, nonces).
Connection error vs stream error
In HTTP/2, a connection error tears down the entire connection (GOAWAY + close); a stream error cancels only one stream (RST_STREAM). Using a connection error for a per-stream fault kills all other in-flight requests unnecessarily.
data.len vs flow_size
data.len = stripped body bytes (padding removed from a DATA frame). flow_size = full wire bytes consumed by the frame including any padding. RFC 7540 §6.9.1: flow-control credit must use flow_size so padding-only frames (data.len==0, flow_size>0) are credited.
diff scope
The set of changes included in the review. Correct: git diff $(merge-base)...HEAD — the full PR contribution. Incorrect: only the latest commit, or @{upstream}...HEAD (empty when just pushed). Under-scoping is the #1 cause of missed findings.
Error scope
The blast radius of an error handler: connection-level (kills all in-flight streams) vs stream-level (kills one stream). A per-stream fault that does return error instead of reset_stream escalates needlessly to connection scope.
Event multiplicity
A boolean flag records at most one occurrence of an event. If the event can repeat before the flag is consumed, a counter is required so each occurrence gets its own response. Example: multiple SETTINGS frames each need their own ACK.
Flag-contract invariant
When a new code path sets a shared flag (s.send_dead = true), every reader of that flag has an implicit contract about what other state must also be true at that moment. The new setter must satisfy every reader's contract — not just set the flag.
Lenient parse
V's string.int(), .u64(), etc. stop at the first non-digit and return the leading number. '200 OK'.int() = 200. A successful parse is NOT input validation. Wire-derived values must have a digit/charset guard at the parse site, not just upstream.
Lock ordering
The declared nesting protocol for mutexes (e.g., wmu → smu → fmu). Acquiring locks in a different order on any code path creates a potential deadlock. Every code path must take locks in the same declared order.
fcv (flow-control condvar)
The sync.Cond in H2MuxConn whose associated lock is fmu. Upload goroutines block in fcv.wait() when the connection-level send window or a stream’s send window is exhausted. Any code path that increases either window, sets s.send_dead = true, or kills the connection must call fcv.broadcast() to wake all blocked senders — missing a broadcast leaves upload goroutines sleeping forever with no further wake-up path.
fmu (flow-control mutex)
The innermost lock in H2MuxConn, guarding all send-side flow-control state: c.send_window (connection send window), c.peer_initial_window, c.peer_max_frame, per-stream s.send_window, and fmu_dead. Also the lock associated with fcv. Declared nesting: wmu → smu → fmu — fmu is always innermost. A nested wmu→fmu acquisition (taking fmu while already holding wmu) is the permitted recheck pattern; the inverse (fmu→wmu) deadlocks with do_on_stream’s wmu→smu→fmu section.
mu / s.mu (per-stream mutex)
The mutex on each H2MuxStream struct, accessed as s.mu when operating on stream s. Guards per-stream state that is local to that stream and distinct from the connection-level locks — stream headers, completion flag, error state. In Transport and TlsIdleConnTracker, mu (without prefix) is the main object mutex guarding pool or tracker state, unrelated to H2 flow control.
mux (H2MuxConn)
Not a mutex. Shorthand for H2MuxConn — the HTTP/2 multiplexed connection that manages multiple concurrent request streams over one TLS connection. When commit messages or comments say “mux lock,” the writer usually means smu (the lock protecting the stream map). The struct itself is the mux; the locks are wmu, smu, fmu, recv_wmu.
recv_wmu (receive-window mutex)
A dedicated mutex in H2MuxConn guarding only conn_recv_window (the connection-level receive flow-control window). Split out from fmu so the reader goroutine can update the receive window without contending with the send-side flow-control state that fmu protects.
smu (stream-map mutex)
The middle lock in H2MuxConn’s nesting order (wmu → smu → fmu), guarding connection lifecycle and the stream map: streams, refs, active_streams, max_streams, peer_max_streams, goaway, goaway_last, closed, shutting_down, transport_torn_down, conn_err, idle_since. The admission gates (can_take_new_request, !c.shutting_down) read fields guarded by smu.
wmu (write mutex)
The outermost lock in H2MuxConn’s nesting order (wmu → smu → fmu). Serializes all writes to the transport — any goroutine sending a frame on the wire must hold wmu. Also guards the HPACK encoder, next_stream_id, handshaked, pending_settings_acks, and pending_ping_acks. Because wmu is outermost, it can nest over fmu (the wmu→fmu recheck pattern) without risk of inversion.
Mechanical check
A grep or shell script that exits non-zero when a defect is present. Preferred over a prose description because prose gets skipped when you "forgot to think about it." A mechanical check is a mandatory gate — it either passes or it doesn't.
Merge base
The commit where the branch diverged from the target branch: git merge-base <base> HEAD. The correct anchor for computing the full PR diff. Using HEAD~1 or @{upstream} instead gives an incorrect (often empty) diff.
Phase A
The adversarial phase (rev 53): independent agents spawned via the Workflow tool, instructed to REFUTE specific findings/functions rather than confirm them. Runs after Phase M, for non-trivial work, as a genuinely separate reviewer — distinct from Phase 3, which only verifies candidates the same self-review pass already found. Standing user opt-in, general to all programming work, not scoped to this repo.
Phase R
The regression phase: when an external reviewer finds a bug this skill missed, Phase R diagnoses whether the angle existed but wasn't run (most common) or was genuinely missing, adds a mechanical check, reproduces it against the reviewed commit, and logs it in the miss corpus.
Sibling handler
Another arm of the same match or if-else chain. A fix applied to one arm is rarely the only arm with the same deficiency. The sibling-handler scan explicitly checks every other arm for the same class of bug.
Swallowed write error
A write/IO failure silenced with or {} that should have set an admission gate (shutting_down, closed). The window between the silent failure and the next gate-setting operation lets other goroutines observe the resource as stale-healthy.
Unbounded accumulation
A peer-driven buffer the reader appends to (c.field <<) or counter it increments (c.field++) per incoming frame, with no size cap. A malicious or buggy peer exhausts memory. Every such accumulator needs an h2_max_* cap or must be provably bounded by the protocol.
unsafe block
A V unsafe { } block that bypasses the compiler's memory-safety guarantees to allow raw pointer arithmetic, direct C interop, or slice manipulation without bounds checks. Each block requires manual review for out-of-bounds access, incorrect lifetime assumptions, and undefined behavior at the C boundary.
wire-integer overflow
Arithmetic on wire-derived values (window sizes, frame lengths, content-length) that silently wraps because V's u32/i32 arithmetic is modular. A u32 + u32 result stored in a u32 can wrap to a small value that passes an upper-bound guard, allowing an oversized frame or window value to be accepted. Guards must operate on a wider type or use explicit overflow checks.
